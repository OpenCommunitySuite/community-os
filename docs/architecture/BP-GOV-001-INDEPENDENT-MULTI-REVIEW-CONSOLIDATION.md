# BP-GOV-001 — Сведение результатов независимых рецензий

**Статус:** Рецензии рассмотрены, решения по спорным вопросам приняты, точечные исправления согласованы  
**Этап:** 11Б  
**Объект:** BP-GOV-001

Этот документ — русскоязычное изложение принятых выводов рецензирования. Исходные отчёты независимых рецензентов и пакет материалов, который им передавался, сохраняются отдельно как исторические источники. Их формулировки могут содержать английскую терминологию и не заменяют принятые нормативные определения.

## 1. Общий итог

Три независимых рецензента пришли к совпадающим основным выводам:

- пересмотр общей предметной концепции не требуется;
- **Реализация права голоса** обоснована как самостоятельный исторически значимый факт в области управления;
- **Результат подсчёта офлайн-части** обоснован как самостоятельный исторически значимый факт в области управления;
- отдельные фундаментальные сущности «Канал», «Бюллетень» и «Подписанное действие» не нужны;
- электронный бюллетень, оформленный документом и подписанный электронной подписью, корректно использует механизмы этапа 11А для открытого голосования;
- для анонимного электронного голосования, осуществляемого самой Community OS, не определена достаточная предметная модель фиксации анонимного выбора;
- безопасное решение для первой нормативной версии — **вариант А: отложить такое анонимное электронное голосование**;
- после точечных исправлений бизнес-процесс можно согласовать с нормативными документами без введения нового предметного контекста.

**Принятое решение: вариант А.** Анонимное электронное голосование, при котором Community OS самостоятельно принимает и обрабатывает анонимный выбор, не входит в первую нормативную версию и первое внедрение этапа 11Б. Его проектирование откладывается на будущее.

Первая нормативная версия поддерживает:

- **Открытое голосование:** бумажные бюллетени; очное и дистанционное участие, если это разрешено правилом; электронный бюллетень в виде подписанного документа; сочетание бумажного и электронного оформления волеизъявлений.
- **Анонимное голосование:** физическая процедура анонимного выбора и подсчёта вне системы; самостоятельная фиксация реализации права голоса там, где это предусмотрено правилом; регистрация результата подсчёта офлайн-части.

Непосредственный приём анонимных электронных голосов внутри Community OS в первой версии не поддерживается.

## 2. Критическое замечание

Существующий **Голос** нельзя использовать без изменений для анонимного электронного голосования, выполняемого самой системой:

```text
Голос → Право голоса → Позиция (содержание выбора)
```

Такая связь нарушает требование невосстановимости связи между участником и его анонимным выбором.

Отдельная сущность для каждого анонимного выбора пока не вводится, поскольку процесс не обосновал её самостоятельную идентичность и жизненный цикл. Повторное или двойное использование относится прежде всего к реализации права голоса. Исправить отдельный анонимный выбор зачастую невозможно, не нарушив анонимности. Проверяемость может обеспечиваться совокупным результатом подсчёта и подтверждающими материалами.

Возвращаться к проектированию этой функции следует, когда применимые правила реально потребуют дистанционного анонимного голосования, проверяемого электронного подсчёта либо использования внешней службы анонимного голосования с признанием её результата в Community OS.

## 3. Реализация права голоса

**Реализация права голоса** остаётся самостоятельным исторически значимым предметным фактом.

Уточнённое определение:

> Согласно действовавшей в соответствующий момент версии правила голосования конкретное право голоса признано реализованным (использованным) для целей этой процедуры.

Сам по себе этот факт **не доказывает автоматически**:

- содержание выбранной позиции;
- признание поданного голоса действительным;
- физический подсчёт бюллетеня;
- участие в процедуре в смысле правила;
- влияние на кворум;
- влияние на результат подсчёта.

Должно быть возможно установить основание признания реализации права, применимую на тот момент версию правила голосования и последствия, которые правило приписывает этому факту.

Выдача или получение бюллетеня создаёт факт реализации права **только если** применимая версия правила прямо определяет соответствующее событие как момент использования права. Иначе это лишь подтверждающее обстоятельство.

Самостоятельная реализация права допустима и при открытом голосовании, когда факт использования права либо участия имеет значение, не совпадающее с признанием конкретного голоса. Не требуется создавать её дубликат для каждого открытого голоса.

**Участие** пока не становится новой фундаментальной сущностью. Это определяемый правилом процедурный факт либо показатель, выводимый из явно перечисленных оснований: подтверждения присутствия, получения бюллетеня, реализации права голоса, признанного голоса и иных фактов, предусмотренных правилом.

## 4. Результат подсчёта офлайн-части

Принята следующая граница предметного факта:

```text
Один результат подсчёта офлайн-части
→ одно голосование
→ один вопрос
→ одна объявленная область подсчёта
```

Один документ с протоколом может подтверждать несколько результатов, каждый из которых относится к собственному вопросу голосования.

Результат подсчёта офлайн-части сам по себе не доказывает участие, кворум, использование права, полноту выданных бюллетеней или окончательно установленный результат голосования. Он служит входными данными для расчёта по количеству выбранных позиций.

Нельзя вводить универсальное правило «один бюллетень = одна единица веса результата». Единицы и вес подсчёта определяет применимое правило голосования. Голосование с неодинаковым весом голосов допустимо только при таком способе подсчёта, который не раскрывает связь между субъектом (его правом голоса) и выбранной позицией.

Для каждого результата должна быть объяснима объявленная область подсчёта. Расчёт обязан исключать двойной учёт при пересечении областей и определять действующий результат или редакцию результата для каждой области. Полнота охвата определяется применимым правилом, а не универсальной формулой.

## 5. Защита анонимности

Запрет восстанавливать связь «Субъект / Право голоса → Позиция» распространяется не только на прямые связи в данных, но и на сопоставление косвенных сведений.

Штатные средства Community OS не должны позволять восстановить такую связь через:

- одинаковые идентификаторы бюллетеня в реестре выдачи и в материалах подсчёта;
- слишком маленькую область подсчёта;
- точное сопоставление времени или места регистрации реализации права и подсчёта;
- промежуточные итоги по слишком малому числу анонимных участников;
- фотографии или сканы отдельных анонимных бюллетеней, позволяющие сопоставить почерк или отметки;
- сведения об исправлении или замене, позволяющие установить конкретного участника.

Применимое правило или профиль сообщества задаёт необходимую степень укрупнения данных и минимальные ограничения для защиты анонимности, когда они требуются.

## 6. Бюллетень с несколькими вопросами

Для открытого голосования допускается:

```text
Один документ, связываемый с подписантом
→ несколько открытых голосов
```

Для каждого голоса необходимо сохранять объяснимую связь с исходной редакцией или представлением документа, конкретным элементом или полем документа, признанной позицией и охватывающей её подписью, когда она требуется. Отдельная сущность «Пункт бюллетеня» не вводится.

Документ, который позволяет определить подписанта или участника, не может содержать позицию по анонимному голосованию. Иначе связи «Подписание → Субъект» и «Элемент документа → Позиция» раскрывают запрещённую связь.

## 7. Различие при исправлениях

Для анонимного голосования:

```text
Исправление факта реализации права голоса
≠ автоматическое исправление анонимного выбора или подсчёта
```

После физического смешивания анонимных бюллетеней нельзя изъять конкретный выбор, не нарушая анонимности.

Если ошибка в регистрации реализации права обнаружена после подсчёта, применимое правило должно предусматривать допустимые последствия: пересмотр результата, повторный подсчёт, если он имеет смысл, анализ существенности ошибки и её влияния, признание процедуры недействительной и повторное голосование либо другое явно предусмотренное решение.

Повторная выдача, испорченный или утраченный бюллетень регулируются явными правилами; право голоса не восстанавливается автоматически и без основания.

## 8. Конфликты и изменение волеизъявления

**Изменение голоса или повторное волеизъявление** — последующее действие, которое применимое правило признаёт допустимой заменой ранее выраженной позиции.

**Конфликт** — несовместимые заявления или действия, которые автоматически не образуют разрешённую замену.

Применимое правило определяет юридически и предметно значимый момент времени: подачу, получение, признание либо другое подтверждаемое событие.

Предложение установить единый для всей платформы закрытый перечень исходов конфликтов отклонено как преждевременное. Вместо этого правило голосования должно явно определять виды конфликтов, основания разрешения и исторически объяснимый исход. Универсальное правило «последнее по времени побеждает» не вводится.

## 9. Режим прозрачности выбора

Каждое конкретное голосование имеет ровно один объявленный режим: **открытый** или **анонимный**.

Режим определяется до начала голосования или приёма волеизъявлений и остаётся неизменным после открытия голосования.

Разные режимы требуют разных самостоятельных голосований. BP-GOV-001 не разрешает объединять открытые и анонимные голосования в один расчёт или установленный результат для обхода этого ограничения. Подобный межпроцедурный механизм потребует отдельного архитектурного рассмотрения.

## 10. Сроки и признание

```text
Волеизъявление получено вовремя
+ признано позднее
≠ автоматически подано с опозданием
```

Применимое правило определяет значимый для процедуры момент времени.

Когда один документ содержит позиции по нескольким вопросам, одно событие получения может подтверждать подачу по нескольким голосованиям, но допустимость и соблюдение срока проверяются отдельно по правилу каждого голосования.

## 11. Совокупные итоги открытого голосования

Для первого внедрения первичным источником сведений об открытом голосовании являются **отдельные признанные голоса**.

Сводный подсчёт может служить средством сверки, контрольной суммой или дополнительным подтверждением.

Процедура открытого голосования, в которой хранятся только сводные итоги без отдельных голосов, этим бизнес-процессом не вводится и потребует отдельного рассмотрения.

## 12. Наименование факта подсчёта

Сохраняется предметное название **«Результат подсчёта офлайн-части» (Result of Offline Count)**. Первая нормативная версия признаёт результат внешнего или физического анонимного подсчёта; собственное анонимное электронное голосование откладывается. Оснований для преждевременного введения универсальной сущности любого подсчёта нет.

## 13. Материалы первого внедрения

Сценарии первого внедрения остаются **ненормативными примерами для проверки модели**, а не общими правилами платформы.

Правило «1 участок = 1 голос» явно обозначается как рабочее правило первого внедрения. Оно **не является универсальным требованием Community OS**. Его юридическая применимость к конкретному товариществу и настройкам управления требует отдельной проверки.

## 14. Согласование нормативных документов

После точечных исправлений критическое замечание считается разрешённым посредством ограничения объёма первой версии. Допускается минимально необходимое согласование документации.

**ADR-001:**
- реализация права голоса не тождественна голосу;
- реализация права может существовать без сохранения выбранной позиции;
- для одного права в одном голосовании действует не более одной признанной реализации на определённый правилом момент;
- основания признания и последствия определяются правилом;
- каждое голосование использует один режим прозрачности выбора.

**ADR-008:**
- результат подсчёта офлайн-части — самостоятельные входные данные для расчёта по конкретному вопросу;
- расчёт может использовать признанные входные сведения, не являющиеся отдельными голосами, если разрешает правило;
- при анонимном подсчёте вне системы сведения об использовании прав отделены от сведений о выбранных позициях;
- исправление реализации права не раскрывает и не исправляет автоматически конкретную анонимную позицию;
- собственное анонимное электронное голосование не входит в первую нормативную версию.

**DOMAIN_MODEL.md:**
- реализация права голоса;
- результат подсчёта офлайн-части;
- явное разграничение связанных фактов;
- происхождение связи между пунктом документа и признанным голосом;
- защита от косвенного восстановления анонимного выбора;
- один режим прозрачности на голосование.

**TERMINOLOGY.md:** нормативные термины и определения, включая разграничения и запреты на ошибочное отождествление.

Новый предметный контекст не требуется.

## 15. Итог рецензирования

**Принять после точечных исправлений → исправления внесены, разрешено согласование с нормативной документацией.**

Пересмотр общей предметной концепции не требуется. Дополнительные фундаментальные сущности не вводятся.

Собственное анонимное электронное голосование остаётся задачей дальнейшего проектирования.
