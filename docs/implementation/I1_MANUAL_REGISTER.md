# Ручной реестр I‑1

Команды предназначены для локальной проверки на синтетических данных в отдельной PostgreSQL. Перед запуском примените `src/CommunityOS.Modules.Community/Infrastructure/Migrations/001_manual_register.sql`, `002_ownership_correction.sql` и `003_register_import.sql` из того же каталога по порядку к этой базе отдельной учётной записью с правом создавать схему. Учётной записи команд реестра нужны `USAGE` на схему и `SELECT` и `INSERT` на её таблицы, а также `UPDATE (subject_id, revision)` на `community_register.ownership`.

Задайте `COMMUNITYOS_REGISTER_DATABASE` со строкой подключения и `COMMUNITYOS_REGISTER_COMMUNITY` с UUID тестового сообщества в текущем сеансе. Используйте отдельные учётные данные для тестовой базы.

```powershell
$owner = dotnet run --project src/CommunityOS.Web -- register add-new "Тестовый собственник" "1" "A-1"
dotnet run --project src/CommunityOS.Web -- register add-existing $owner "2" "A-2"
dotnet run --project src/CommunityOS.Web -- register list
```

В списке ожидаются два участка с одним идентификатором собственника и разными номерами счетов. Операция добавления записывает участок, связь собственности и счёт в одной транзакции. Для второго участка собственника выбирают по идентификатору. Совпадение имён само по себе ничего не связывает.

Это первый сценарий ручного ввода. Для работы с данными пилота нужны отдельные сценарии доступа и интерфейс администратора. CSV/XLSX относится к следующей части I‑1.

Если при первоначальном вводе привязали не того собственника, возьмите `PlotId` и `OwnershipRevision` из результата `register list` и укажите UUID правильного собственника того же сообщества.

```powershell
dotnet run --project src/CommunityOS.Web -- register correct-owner $plotId $revision $correctOwner "Ошибка первоначального ввода"
```

Исправление сохраняет прежнюю связь и причину в `community_register.ownership_correction`, а счёт остаётся привязан к участку. Повтор команды с устаревшей ревизией отклоняется. Команда предназначена для исправления ввода. Фактическая смена собственника требует отдельного процесса.

## Предпросмотр начальной загрузки CSV

Для проверки на синтетических данных используйте CSV с заголовком и разделителем-запятой. Одна запись описывает один участок с одним собственником и одним лицевым счётом.

```csv
plot_number,owner_key,owner_name,account_number
1,S-001,Тестовый собственник,A-1
2,S-001,Тестовый собственник,A-2
```

```powershell
dotnet run --project src/CommunityOS.Web -- register preview-import .\register.csv
```

В JSON отдельно показаны предполагаемые действия для участка, собственника, связи собственности, счёта и его привязки. `OwnerKey` — явный ключ из исходных данных, используемый в пределах файла. Совпадение имён при разных ключах не объединяет собственников. Повтор номера участка или счёта в файле, совпадение с действующим реестром и противоречивые имена для одного ключа блокируют план. Нумерация `Row` относится к записям CSV, включая заголовок.

Предпросмотр только читает реестр. `CanProceed` означает, что этот предварительный план не содержит обнаруженных конфликтов. Готовый план содержит `PlanId`, который используется при подтверждении.

## Предпросмотр экспорта OSBBX

```powershell
dotnet run --project src/CommunityOS.Web -- register preview-import .\osbbx.xlsx
```

Команда читает лист «Власники» и сопоставляет колонки «Номер ділянки», «ПІБ» и «Особовий рахунок». Номер счёта должен быть записан в XLSX как текст, чтобы сохранить ведущие нули. `Row` указывает номер строки Excel.

Поле «ПІБ» показано в предпросмотре в исходном виде. Это поле может содержать нескольких лиц, прежнего собственника или пояснение, поэтому для каждой строки нужно подтвердить, кого она обозначает. Повторяющиеся значения дополнительно отмечаются, а связи собственности остаются заблокированными. Лист «Лічильники» относится к следующему этапу учёта ресурсов. Используйте синтетическую копию для демонстраций. Вывод предпросмотра содержит имена из входного файла.

## Подтверждение и применение плана

Для обычного CSV запустите `preview-import <file.csv>`. Для экспорта OSBBX подготовьте отдельный CSV решений с теми же колонками `plot_number,owner_key,owner_name,account_number`. Для каждого участка укажите проверенное имя и ключ собственника. Одинаковый ключ используйте только для участков, которые подтверждённо относятся к одному лицу. Номера участка и счёта должны совпадать с исходным XLSX.

```powershell
dotnet run --project src/CommunityOS.Web -- register preview-import .\osbbx.xlsx .\decisions.csv
dotnet run --project src/CommunityOS.Web -- register apply-import .\osbbx.xlsx $planId .\decisions.csv
```

Для обычного CSV опустите `decisions.csv` в обеих командах. Перед применением проверьте план, возьмите `PlanId` из его вывода и задайте `COMMUNITYOS_REGISTER_OPERATOR` с идентификатором подтвердившего оператора. В локальном сценарии этот идентификатор вводится вручную.

Применение проверяет, что строки и решения соответствуют идентификатору плана, повторно сверяет номера с реестром и записывает весь пакет одной транзакцией. Повтор того же плана возвращает `AlreadyApplied`. В журнале остаются идентификатор плана, оператор и связь строк источника с созданными участками и субъектами. Это начальная загрузка новых записей. Сопоставление с ранее созданными собственниками, обновление из изменившейся выгрузки и интерфейс подтверждения для работы с реальными данными требуют отдельных сценариев.

### Локальная проверка в браузере

Сохраните исходный предпросмотр OSBBX в JSON. Код завершения `1` ожидаем, пока собственники требуют проверки.

```powershell
dotnet run --project src/CommunityOS.Web -- register preview-import .\osbbx.xlsx |
    Set-Content -Encoding utf8 .\osbbx-preview.json
```

Откройте `tools/register/osbbx-review.html` локально и выберите `osbbx-preview.json`. Страница выделит повторяющиеся значения «ПІБ» и предложит ввести проверенные имена и ключи. Когда решения заполнены, скачайте `decisions.csv` и вернитесь к предпросмотру с файлом решений. Перед закрытием страницы сохраните готовый CSV. Введённые решения хранятся только во вкладке, а исходный JSON и скачанный CSV содержат сведения о собственниках. Скачанный CSV предназначен для команды импорта.

Это локальный инструмент подготовки решений. Применение плана выполняется отдельной командой.
