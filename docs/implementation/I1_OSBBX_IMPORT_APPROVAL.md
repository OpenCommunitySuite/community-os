# I‑1. Утверждение начального импорта OSBBX

Статус: проект для синтетического стенда. Основания — ADR‑012, ADR‑015, ADR‑018, Implementation Baseline и [проект доступа оператора I‑1](I1_OPERATOR_ACCESS_REVIEW.md).

Подготовщик с действующим правом подготовки передаёт конкретную ревизию личного черновика. Сервер рассчитывает идентификатор плана из сообщества, исходных строк и проверенных решений. Передача фиксирует идентификатор плана и ревизию. Утверждающий получает доступ к переданному плану по отдельному назначению в том же сообществе. На стенде используются разные учётные записи и субъекты. Правила выдачи прав, подтверждения основания и совмещения ролей в эксплуатации остаются открытыми.

При подтверждении Platform PostgreSQL проверяет активность сессии, связь с субъектом, состояние сообщества, доступность функции, право применения и предметное основание. Блокировки авторитетных строк сериализуют отзыв и фиксацию допуска. Применение в Community PostgreSQL начинается после подтверждённой фиксации допуска. Если отзыв зафиксирован раньше допуска, запись отклоняется. Допуск содержит идентификаторы утверждающего и плана, ревизию и основание, полученное с сервера.

Транзакция Community блокирует черновик и повторно проверяет переданную ревизию и идентификатор плана. Изменение решений до этой проверки делает передачу устаревшей. Транзакция повторно проверяет конфликты и применяет пакет через существующее хранилище импорта. Ограничения уникальности защищают также от изменений реестра, совершённых после проверки. При конфликте откатывается весь пакет. Повтор применённого плана возвращает прежний результат.

Допуск передачи и допуск применения связаны с сообществом, черновиком, ревизией и идентификатором плана. При неопределённом результате фиксации допуска сервер не начинает запись в Community PostgreSQL. Повторный запрос проходит проверку действующих полномочий заново.

На стенде ранее переданная ревизия сохраняет силу после отзыва права подготовщика, пока её решения не изменены. При применении проверяется действующее полномочие утверждающего. Совпадение с подготовщиком по учётной записи или субъекту блокирует подтверждение.

Отчёт строится по результату конкретной передачи и доступен обладателю действующего права утверждения в соответствующем сообществе. Точный повтор успешной передачи сообщает о повторе, а отчёт сохраняет идентификатор первоначального утверждающего даже при последующем изменении черновика. Другая передача с тем же планом не получает доступ к прежнему результату. Журнал фиксирует допуск, результат, субъект и предметное основание. Персональные данные и строки исходной выгрузки хранятся в реестре и черновике.
