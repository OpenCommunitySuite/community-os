# I‑1. Подготовка импорта OSBBX в Community Application

Синтетический сценарий продолжает [ручной реестр](I1_WEB_MANUAL_REGISTER.md) и [проект доступа оператора](I1_OPERATOR_ACCESS_REVIEW.md). Подготовка импорта требует отдельного разрешения и действующей связи учётной записи с субъектом. Для чтения и изменения черновика сервер проверяет сообщество, учётную запись и действующего субъекта. Совместное редактирование и порядок эксплуатационной выдачи права требуют отдельного решения.

Черновик хранит отпечаток SHA‑256 исходного XLSX и извлечённые строки. Исходный архив обрабатывается в памяти в пределах ограничений загрузки. При повторном открытии используется сохранённый источник. Решения указывают строку Excel, проверенное имя и явный ключ собственника в пределах черновика. Ревизия черновика защищает решения от перезаписи параллельным запросом. Предпросмотр заново читает реестр выбранного сообщества и показывает текущие конфликты. Участки, собственники и счета при подготовке не меняются.

Веб-загрузка ограничивает размер архива, распакованных частей, число строк и объём полей. Формулы в используемых колонках отклоняются. Сервер возвращает общую ошибку повреждённого формата без содержимого ячеек. Значения строк и решения сохраняются только в черновике и не выводятся в журналы.

Право подготовки включает проверку существования номеров участка и счёта, переданных в выбранной выгрузке. В ответе оператор получает признаки конфликтов для этих номеров. Для самостоятельного просмотра записей реестра требуется право чтения.

Запись черновика начинается после подтверждённой фиксации допуска в Platform PostgreSQL. Отзыв, зафиксированный раньше допуска, блокирует запись. Допуск хранит идентификаторы сообщества, учётной записи и субъекта. Для эксплуатации отдельно определяются сроки хранения, квоты, удаление и журналирование отказов. Список черновиков на стенде показывает последние 100 записей оператора.
