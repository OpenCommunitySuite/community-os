# I‑1. Исправление ошибочной привязки собственника

Статус: проект для закрытого синтетического стенда. Основания — ADR‑012, ADR‑015, ADR‑018, Implementation Baseline и [проект доступа оператора](I1_OPERATOR_ACCESS_REVIEW.md).

Оператор с правами чтения и исправления и предметным основанием указывает участок, текущую ревизию, другого существующего собственника и причину. Право чтения позволяет просматривать историю в своём сообществе. Порядок выдачи прав и подтверждения основания для эксплуатации требует отдельного решения.

Platform PostgreSQL проверяет сессию, связь с субъектом, доступность сообщества, право исправления и основание под блокировками. Подтверждённая фиксация допуска открывает запись в Community PostgreSQL. Отзыв до фиксации блокирует исправление. Допуск связывается с сообществом, участком, исходной ревизией и целевым субъектом.

Community PostgreSQL атомарно обновляет связь по исходной ревизии, фиксирует предметную историю и записывает результат в отдельный журнал. Устаревшая ревизия отклоняется. Составной внешний ключ исключает связь с субъектом другого сообщества. Если подтверждение фиксации потеряно, оператор перечитывает связь и историю. Повтор со старой ревизией не создаёт второе исправление. Участок, лицевой счёт и исходный отчёт импорта сохраняются.

В истории видны прежний и исправленный собственники, причина, время, учётная запись и действующий субъект. Ранние CLI-записи сохраняются с имеющейся атрибуцией. Журнал результата содержит идентификаторы допуска, сообщества, участка и оператора, время и результат. Имена собственников и текст причины доступны через защищённую историю.

На стенде сервер проверяет право чтения заново при запросе истории. Для эксплуатации следует отдельно утвердить видимость причин. Журнал различает исправление, устаревшую ревизию, недоступного собственника и выбор текущего собственника. Предметное основание берётся из серверного назначения.
