# I‑1. Ручной реестр в Community Application

Статус: проект для синтетической проверки. Основания — ADR‑012, ADR‑015, ADR‑018, Implementation Baseline и проект доступа оператора I‑1.

## Доступ

Community Application использует действующую платформенную сессию. Для каждого запроса сервер заново проверяет активность учётной записи, связь с субъектом, доступность сообщества и функции реестра, а также разрешение на запрошенное действие. Список сообществ содержит только доступные оператору записи. Идентификатор сообщества из запроса используется для выбора контекста. Роли суперадминистратора и первого технического администратора проверку прав реестра не заменяют.

Для чтения и ручного внесения используются отдельные разрешения. Для внесения также требуется действующее предметное основание. Тестовые разрешения и основания подготавливаются доверенным оператором стенда для синтетических субъектов. Оба тестовых сообщества размещены в отдельной базе реестра стенда. Маршрут включается только явной настройкой `CommunityRegister:SyntheticStandEnabled`. Для эксплуатации требуется утвердить порядок выдачи прав и подтверждения основания и подключить авторитетные источники связи, жизненного цикла, Entitlement и Placement.

## Граница принятия записи

Реестр хранится отдельно от платформенных сессий. Перед внесением сервер блокирует записи сессии, связи, разрешения и доступности, повторно проверяет срок действия сессии и фиксирует допуск в Platform PostgreSQL. Изменения доступа сериализуются с этой транзакцией. Граница принятия — фиксация допуска. Сервер начинает запись реестра после подтверждения фиксации платформенной БД. При неопределённом результате фиксации сервер не начинает запись реестра. Допуск подтверждает право исполнить запрос и сам по себе не подтверждает результат записи.

Операция добавления использует существующую логику реестра. Участок, связь собственности, лицевой счёт и сведения о том, кто внёс запись и на каком основании, сохраняются одной транзакцией вместе с идентификатором допуска. Привязка к существующему собственнику выполняется по идентификатору в пределах проверенного сообщества. Запись, уже допущенная к исполнению, сохраняет исходную атрибуцию при последующем отзыве.
