# I‑2. Деревья точек учёта электроэнергии

Для публикации предусмотрено отдельное право с основанием. Platform сохраняет допуск с датой редакции до записи в Community. Редакция сохраняет ссылку на допуск. После отзыва права новые допуски не выдаются. Все точки редакции записываются одной транзакцией. Параллельные публикации одного сообщества сериализуются. Допуск может остаться после отклонённой записи и сам по себе не означает публикацию.

Основания — ADR‑007 §20, ADR‑012, ADR‑015, ADR‑018 и план внедрения пилота.

Для пилотного сценария дерево состоит из корневой точки на ТП, контрольных точек улиц и индивидуальных точек участков. Одна ТП может содержать несколько независимых корней. В дереве используются идентификаторы точек учёта. Замена прибора не меняет связь точки с ветвью. Общая точка может оставаться вне дерева, пока её роль не определена.

Датированная редакция описывает весь лес сообщества. На дату измерения применяется последняя редакция, действующая с этой даты или раньше. До первой редакции топология отсутствует. Публикация редакции атомарна, её дата должна быть позже даты предыдущей редакции. Смена ветви с новой даты не меняет предыдущую редакцию. Порядок исправления уже опубликованных исторических связей рассматривается отдельно.

В одной редакции точка имеет одно положение. Корень связан с ТП, контрольная точка — с корнем, индивидуальная — с контрольной точкой. При публикации проверяются тип точки и принадлежность всех объектов сообществу. Просмотр требует права чтения электроэнергии. Публикация требует отдельного серверного допуска и защиты CSRF. Топология не меняет собственность, лицевые счета и порядок признания показаний.

Приёмка на синтетическом стенде охватывает две ТП и три корня, включая два корня на одной ТП, пути к участкам, смену ветви с сохранением прежнего пути на дату измерения, замену прибора, изоляцию сообществ и отказ при нарушении иерархии. Сверка небаланса и начисления выходят за рамки этого шага.
