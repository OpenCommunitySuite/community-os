# I‑2. Замена индивидуального электросчётчика

Статус: проект первого сценария для закрытого синтетического стенда. Основания — ADR‑007, ADR‑012, ADR‑015, ADR‑018, BP‑METER‑001, BP‑READING‑001 и Implementation Baseline.

## Сценарий

Оператор выбирает действующую установку на индивидуальной точке, указывает общую календарную дату окончания измерительного использования старого прибора и начала использования нового, инвентарное обозначение и причину. Точка учёта и участок сохраняют идентификаторы. Старая установка закрывается, новый прибор и его установка регистрируются в одной транзакции. История показывает обе установки, дату и сведения о регистрации замены. Сценарий рассчитан на непрерывную замену совместимым прибором с одним накопительным каналом прямого измерения в кВт·ч.

Даты имеют календарную точность по Europe/Kyiv. Замена вступает в силу с указанной даты. Старая установка учитывает обычные дневные показания до этой даты, новая — с неё включительно. Дата замены должна быть позже начала старой установки и не позже текущей даты. Если на эту дату или позже уже есть признанные показания старого прибора, оператор получает конфликт для отдельного разрешения.

Запоздалое дневное показание вводится с явным выбором исторической установки и проверяется по её интервалу. Граничные показания требуют отдельного сценария с явной семантикой границы. Регистрация замены допустима без них. История отдельно показывает недостаточность граничных данных старого и нового прибора. Ближайшие дневные значения не подставляются вместо граничных. Разницы рассчитываются внутри каждой установки.

## Полномочия и конкуренция

Для замены требуется действующая сессия, связь с субъектом, доступность функции, право чтения электроэнергии, отдельное право замены и серверное предметное основание. Оператор также указывает фактическую причину замены. Допуск фиксируется в Platform PostgreSQL до начала записи. Порядок выдачи прав и подтверждения оснований для эксплуатации остаётся отдельным решением.

Транзакция замены блокирует старую установку тем же способом, что и признание показания. После блокировки сервер повторно проверяет интервал и существующие показания. Повтор с тем же идентификатором запроса и теми же данными возвращает ранее зарегистрированную замену. Изменение данных при том же идентификаторе либо конкурирующая замена уже закрытой установки отклоняются. Оператор получает историю прежних и новых показаний только в своём сообществе.

Форма сохраняет идентификатор для повторной отправки в открытой вкладке. Если ответ потерян и страница уже перезагружена, оператор сверяет результат по истории установок.

Приёмка охватывает сохранение точки и истории, замену без граничных значений, конфликт с ранее признанным показанием, одновременные запросы, отзыв права, CSRF и изоляцию сообществ. Разрыв между установками, повторная установка использованного прибора, исправление факта замены, многотарифность и начисления остаются отдельными сценариями.
