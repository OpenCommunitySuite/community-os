# I‑2. Пакетный импорт показаний электроэнергии

Первый сценарий проверяется на синтетическом стенде в рамках ADR‑007, ADR‑011, BP‑READING‑001 и проекта BP‑READING‑002. Для импорта выбран шаблон CSV с заголовком `installation_id,measured_on,channel,value_kwh`. Он использует внутренний UUID уже зарегистрированной установки. Сопоставление внешних идентификаторов приборов потребует отдельного контракта источника. UUID точки, номер участка и обозначение прибора сами по себе не определяют установку.

Договорённость для шаблона — UTF‑8, разделитель запятая, одна запись на строку, без кавычек, дата `yyyy-MM-dd`, регистр `total`, `day` или `night`, исходное накопительное значение в кВт·ч с десятичной точкой и не более чем тремя дробными знаками. Файл ограничен 128 КиБ и 500 записями. Номер строки сохраняется в отчёте.

Перед применением оператор сверяет распознанные строки. Дата проверяется по выбранной исторической установке, регистр — по конфигурации прибора. После подтверждения строки передаются существующей операции признания. Результат фиксируется для каждой строки. Повтор совпадающего показания возвращает прежнюю запись, конфликтующее значение отклоняется, запоздалое оценивается по соседним датам. Коэффициент применяется при расчёте потребления по установке. Из файла сохраняется исходное значение без умножения.

Чтение и запись ограничены сообществом. Применение требует действующего допуска и защиты CSRF. Признанное показание сохраняет источник импорта, основание и ссылку на допуск. Подключение внешних систем, импорт воды, исправление ранее признанных значений и эксплуатационные назначения рассматриваются отдельно.

Предпросмотр использует действующее право чтения электроэнергии. Применение повторно проверяет действующее право признания для каждой корректной строки и сохраняет существующий допуск Platform с конкретной установкой, датой и регистром до записи в Community. Новое полномочие не вводится. Подтверждение отправляет тот же CSV и его SHA‑256 из предпросмотра. Применение повторяет проверку данных на актуальном состоянии. Транзакция отдельна для каждой строки. Если право отозвано во время обработки, уже признанные строки сохраняются, а новые допуски не выдаются.

## Сквозная приёмка применения

Режим `csv-import` в [инструкции стенда](../../ops/test-stand/README.md) работает в отдельном синтетическом сообществе с установкой одного регистра и коэффициентом 40. Смешанный CSV содержит значения 100 и 103 на 01.01/03.01.2026, недопустимое запоздалое 104 и допустимое 101 на 02.01, повтор, конфликт даты, неверную дату и неподдерживаемый канал. Предпросмотр не изменяет историю. Применение через форму сохраняет три показания с источником `csv-import`, даёт интервалы 40 и 80 кВт·ч и построчные отказы.

Повторное применение сохраняет прежние записи и атрибуцию; результат строки может измениться с `Decreasing` на `DateConflict`, поскольку допустимое промежуточное показание уже признано. Проверяются несовпадение SHA‑256, CSRF и отказ из открытой формы после отзыва права. Чтение и предпросмотр остаются доступны, кнопка применения после перезагрузки скрыта. Сверяются таблица отчёта, исходные записи и их допуски Platform. Этот прогон не проверяет отзыв посреди одного пакета, двухрегистровый импорт или внешнее сопоставление идентификаторов.

## Контекстная справка и синтетическая проверка

В области «Імпорт показань CSV» доступна справка и руководство из общего текста на украинском языке. Они объясняют UUID установки, точный шаблон, исходное значение без коэффициента, предпросмотр, отдельное применение, построчные отказы и возможность частичного результата. Для читателя доступен предпросмотр; применение требует существующего права признания.

Существующий браузерный прогон электроэнергии сверяет общий текст, отсутствие предпросмотра без файла, синтетический CSV с повтором существующего показания и некорректной датой, отказ неверного заголовка, клиентский лимит размера и сброс предпросмотра при смене файла. Применение не выполняется: разрешён только POST конкретного предпросмотра, остальные запросы записи блокируются. Проверить читателя без кнопки применения и оператора, Escape/фокус, окно 390 px и снятие выбора сообщества. Действующие интеграционные проверки применения сохраняются; полномочия и правила импорта не меняются.

## CSV после замены прибора

Режим `csv-import-history` выполняет замену через форму на 04.01.2026 до импорта: прежняя установка сохраняет коэффициент 40, новая получает 1. К восьми смешанным строкам добавлены старое показание 104 на дату замены и новые 1 → 4 на 04.01/05.01. Старое значение на границе отклоняется в предпросмотре и применении. Исторические интервалы остаются 40/80 кВт·ч, новый ряд даёт 3 кВт·ч; исходные значения и ссылки граничных показаний сверяются отдельно.

Повтор сохраняет идентификаторы и атрибуцию обоих рядов. В UI проверяются одиннадцать результатов импорта, выбор истории установок, показания и интервалы. Сверка баз подтверждает пять CSV-показаний, двадцать допусков попыток признания и одну замену с собственным допуском. После отзыва права признания применение отклоняется, а чтение обоих рядов и предпросмотр сохраняются. Дополнительное право замены выдаётся только новому синтетическому сообществу и отзывается при очистке.

Колонка «Джерело» показывает «Імпорт CSV» для показаний из файла и «Ручне спостереження» для введённых вручную. Браузерные сценарии `csv-import-history` и `manual-readings` проверяют обе подписи.

Режим `csv-import-dual` импортирует шесть дневных и ночных показаний в двухрегистровую установку. Строка с регистром `total` отклоняется. При коэффициенте 40 дневной ряд даёт 120/120 кВт·ч, ночной — 40/80 кВт·ч, а сумма по совпадающим границам составляет 160/200 кВт·ч. Сценарий проверяет подписи источника, связь показаний с допусками, неизменность рядов при повторе и отказ применения после отзыва права.

## Отзыв во время обработки CSV

Ревью границы записи. Platform фиксирует допуск до начала записи Community, а применение заново проверяет право для следующей строки. Стенд удерживает блокировку одной синтетической установки. После фиксации первого допуска и до записи первого показания стенд отзывает право признания и снимает блокировку. Ожидается завершение первой строки по выданному допуску, отказ для следующих корректных строк в том же ответе и сохранение права на чтение. В обеих базах должно остаться ровно по одной связанной записи. Это проверка действующего договора без изменения полномочий приложения.

Режим `csv-import-revocation` проверяет три допустимые строки в одном запросе. Таблица результатов показывает одно признанное показание и два отказа «Дозвіл відкликано». Повтор применения получает HTTP 403. Чтение и предпросмотр доступны, а признанное показание и связанный допуск сохраняются с исходной атрибуцией.
