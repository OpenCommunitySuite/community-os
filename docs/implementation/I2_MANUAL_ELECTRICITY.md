# I‑2. Ручное признание показаний электроэнергии

Статус: проект для закрытого синтетического стенда. Основания — ADR‑007, ADR‑012, ADR‑015, ADR‑018, BP‑READING‑001, Implementation Baseline и дорожная карта пилота.

## Точка, прибор и установка

Оператор выбирает участок из I‑1. Точка имеет собственный идентификатор и связана с участком, прибор имеет отдельный идентификатор и обозначение, установка связывает прибор с точкой с указанной календарной даты. Первый сценарий поддерживает одну индивидуальную точку электроэнергии на участок, один прибор на точку и один накопительный канал в кВт·ч. Установка открыта с даты начала. Замена и закрытие установки требуют отдельного процесса.

## Признание и расчёт

Сценарий хранит календарную дату измерения с точностью до дня. На стенде будущие даты определяются по календарю Europe/Kyiv. Дата должна приходиться на действующую установку. Оператор непосредственно снял значение и явно подтверждает его признание. Сохраняются идентификатор показания, дата измерения, накопительное значение с точностью до 0,001 кВт·ч, источник ручного наблюдения, версия правила, время признания, учётная запись и действующий субъект.

Совпадающая дата и значение возвращают результат «уже записано» с исходной атрибуцией. Правило оставляет одно дневное показание этого канала и не устанавливает идентичность физических наблюдений. Другое значение на ту же дату требует разрешения конфликта. Запоздалое показание проверяется относительно обоих соседей по дате. Равное значение допустимо. Допустимы значения от 0 до 999999999999,999 без округления. Проверка и запись сериализуются в пределах установки. Отказы не меняют историю.

Расчётная оценка потребления показывает разницу соседних признанных показаний этой установки в порядке дат. Результат содержит границы интервала и ссылки на исходные показания. При одном показании интервал ещё не определён. Позднее показание меняет разбиение проекции, сохраняя историю признания. Самостоятельный предметный факт Consumption и финансовые записи в этом сценарии не создаются.

## Доступ

Для чтения, настройки точки и признания используются отдельные тестовые разрешения. Для записи требуется текущее право чтения, право соответствующего действия и предметное основание. Сервер проверяет сессию, связь с субъектом, состояние сообщества и доступность функции. Отзыв, зафиксированный до допуска в Platform PostgreSQL, блокирует действие. Запись в Community PostgreSQL начинается после подтверждения допуска. Идентификаторы участка, точки, прибора и установки проверяются в пределах выбранного сообщества. Порядок выдачи прав и подтверждения оснований для эксплуатации требует отдельного решения.

Для стенда оператор одновременно наблюдает и признаёт значение. Источник, версия правила, серверное основание и идентификатор допуска сохраняются с показанием. Допуск содержит вид действия, сообщество, участок или установку и предметную дату. Установка начинается включительно. Обозначение прибора используется как уникальный инвентарный идентификатор в сообществе.

Право чтения ресурса открывает номера участков в селекторе. Имена собственников и данные лицевых счетов доступны по правилам реестра I‑1. Установка создаётся без начального показания. Вода, общие и контрольные точки, несколько каналов, замена прибора, импорт, исправление показаний и начисления относятся к следующим сценариям.
