# I‑4. Приём наличных от известного плательщика

Первый сценарий по ADR‑006 и BP‑CASH‑001 связывает самостоятельный факт физического приёма наличных с одним обычным платежом на всю сумму в гривнах. Дата приёма вводится кассиром, время регистрации фиксирует сервер. Распределение выполняется отдельной командой по BP‑FIN‑ALLOCATION‑001.

## Ревью доступа и согласованности

Отдельное основание кассира проверяется через активную сессию и действующее назначение в выбранном сообществе. Право приёма не даёт права распределения. Platform фиксирует допуск с действием, идентификатором команды и её отпечатком перед транзакцией Community. Фильтр CSRF применяется к записи. Отзыв блокирует новые допуски, в том числе при повторе. Уже выданный допуск может завершиться.

Транзакция Community записывает платёж и факт приёма вместе. Оба идентификатора принадлежат сообществу, связь уникальна для этого сценария. Отпечаток команды включает канал, поэтому повтор команды ручной записи с идентификатором кассового платежа отклоняется. При совпадении отпечатка возвращается исходный идентификатор платежа. Дата приёма, сумма и плательщик фиксируются в обеих записях одной командой. Просмотр истории требует финансового доступа.
